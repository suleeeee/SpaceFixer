# SpaceFixer

一个用于检查并修复 Figma 文本空格的本地插件。

正式 Plugin ID：`1648025602357999016`

## 功能

- 默认开启 `补充缺失空格`，检查中文与英文或普通数字之间缺少的空格；默认勾选 `排除角标`，因此角标默认不参与缺失空格检查。
- 扫描范围默认是当前页面，也支持整个文件或选中内容。
- 齿轮按钮打开独立规则设置页，扫描设置、补充规则和清理规则分别分组。
- 扫描设置中默认开启 `跳过隐藏图层`，文本自身或任一父级图层隐藏时不会参与检查。
- `补充缺失空格`设置包含：补充中文与英文/普通数字之间 1 个空格，默认开启；排除角标，默认开启。
- 支持可选的 `清理多余空格`，主开关默认不勾选。开启后按规则设置清理对应字符边界。
- `清理多余空格`开启后，默认勾选：删除行首、行尾空格；删除中文与中文、中文与标点符号之间的空格；删除角标左右空格；将中文与英文/数字、英文与英文/数字、数字与数字之间的多个空格压缩为 1 个。
- `清理多余空格`开启后，默认不勾选：删除数字与数字之间空格（谨慎使用）。
- 规则设置面板支持一键恢复默认值，会同时恢复扫描设置、补充规则和清理规则。
- 每项详细规则均可独立关闭，关闭后只影响对应字符边界。
- `补充缺失空格`与`清理多余空格`至少需要开启一项；两项都关闭时检查按钮不可用。
- 点击单条结果的 `定位` 后，会用 Figma 原生文本选区临时选中当前问题字符，不修改文案颜色、不创建临时图层。
- 支持单条修复或全部修复；单条问题会直接修复，全部修复会先展示确认预览。
- 单条修复后只重新检查当前文本图层，不重新扫描整页或整个文件。
- 全部修复预览会汇总受影响图层、缺少空格、多余空格和术语格式问题数量。
- 修改扫描范围、检查选项或术语规则后，旧结果会保留供查看，但修复操作会暂停，直到重新检查。
- 支持当前文件共享和个人两层术语规则，检测时始终合并使用。
- 当前文件共享术语规则随 Figma 文件保存，团队成员在同一文件中运行插件即可读取。
- 个人术语规则只保存在当前用户的本机，不影响团队成员。
- 支持术语规则，避免 `蓝心小V`、`小V圈搜`、`iQOO 智能双面夹5 Pro`、`iPhone`、`ChatGPT`、`OpenAI` 等名称内部被错误修改。
- 支持检查术语内部被错误拆开的空格，例如 `蓝心小 V`、`小 V圈搜`、`Chat GPT`。
- 当前文件共享术语规则和个人术语规则都会自动保存。
- 插件初始使用 `420 × 520px` 紧凑窗口；发现问题、打开全部修复预览或展开术语规则时扩展到 `420 × 760px`。
- 检查结果使用主要工作区；术语规则显示为 `术语规则（白名单）`，空词库首次打开时默认展开，并用精简输入态降低信息负担；已有术语时默认折叠。

## 导入方式

1. 打开 Figma。
2. 进入 `Plugins > Development > Import plugin from manifest...`。
3. 选择本目录下的 `manifest.json`。
4. 运行 `SpaceFixer`。

换电脑后仍使用同一个 `manifest.json` 和正式 Plugin ID。`当前文件共享`术语随 Figma 文件保存；`仅我使用`术语保存在本机，需要手动复制到新电脑。

## 检查规则

插件会检查以下相邻字符：

- `中文A` -> `中文 A`
- `A中文` -> `A 中文`
- `中文1` -> `中文 1`
- `1中文` -> `1 中文`

开启 `清理多余空格` 后，会额外执行以下规则：

- 每行开头和结尾的横向空格会被删除。
- `中文  中文` -> `中文中文`，中文字符之间只要存在空格就会清除。
- `12 34` 默认保持不变；`12  34` 默认压缩为 `12 34`；开启“删除数字与数字之间空格（谨慎使用）”后修复为 `1234`。
- `中文  English` -> `中文 English`，中文与英文/数字之间超过 1 个空格时压缩为 1 个。
- `中文  123` -> `中文 123`，中文与英文/数字之间超过 1 个空格时压缩为 1 个。
- `中文  ，说明` -> `中文，说明`，中文与中文标点之间的空格会被删除。
- `佩戴 ¹` -> `佩戴¹`，角标左右的横向空格会被删除，不要求另一侧必须是中文。
- `Pro ¹` -> `Pro¹`，英文与角标之间的横向空格也会被删除。
- `¹ ²` -> `¹²`，数字角标内部的空格会被删除。
- `Hello  World` -> `Hello World`，英文与英文/数字之间超过 1 个空格时压缩为 1 个。
- `Version  2` -> `Version 2`，英文与英文/数字之间超过 1 个空格时压缩为 1 个。
- 英文与英文之间缺少空格时不检查，已有的单个空格也保持不变。
- 术语规则内部的空格以用户输入格式为准，不会被该选项覆盖。
- 普通空格、全角空格 `U+3000`、不换行空格等横向空白会按相同边界规则识别；回车和 Unicode 行分隔符不会被当作空格删除。

该选项可能误删设计师或文案刻意保留的空格，因此界面默认关闭，并在勾选后显示风险和规则说明。

`排除角标` 和 `删除角标左右空格` 默认都开启：前者让角标不参与缺失空格检查，后者在开启 `清理多余空格` 后清理角标左右已有的横向空格。取消 `排除角标` 后，角标会参与缺失空格检查，此时 `删除角标左右空格` 会自动关闭并不可选，避免同一处空格被重复验证。

这里的“普通数字”不包含 Unicode 上下标数字，也不包含带 OpenType `SUPS` / `SUBS` 的数字角标。

默认开启 `跳过隐藏图层` 时，Figma 中被隐藏的文本图层，以及位于隐藏 Frame、Group、Component 等父级中的文本，都不会出现在检查结果中。

术语规则中的完整术语会被当作一个整体，插件只保护术语内部的相邻字符，不保护术语和外部文案的边界。

例如：

- 术语规则有 `蓝心小V` 时，`蓝心小V生活` 会被修复为 `蓝心小V 生活`，但不会变成 `蓝心小 V 生活`。
- 术语规则有 `蓝心小V` 时，`蓝心小 V生活` 会被修复为 `蓝心小V 生活`。
- 术语规则有 `小V圈搜` 时，`使用小V圈搜查找内容` 会保持术语内部格式。
- 术语规则有 `iQOO 智能双面夹5 Pro` 时，术语内部的空格会按输入格式检查。
- 术语规则有 `ChatGPT` 时，`Chat GPT` 会被修复为 `ChatGPT`。
- 术语规则只会修复同一行中的多余空格；设计师手动输入的回车和换行不会被删除。

术语规则也可以写完整混合短语，例如 `iPhone 16 Pro`、`OpenAI API`、`macOS Sequoia`。

## 团队共享术语规则

术语规则分为两层：

- `当前文件共享`：默认编辑范围，保存在当前 Figma 文件中，所有拥有文件编辑权限的成员均可共享。
- `仅我使用`：仅保存在本地，只影响当前用户。

检测和修复时会始终合并两层词库。范围下拉框只决定当前查看和编辑哪一层，不会关闭另一层。`清空当前` 只会清空正在查看的词库。

跨多个 Figma 文件或不同电脑迁移词库时，直接复制文本框中的术语，并粘贴到目标文件的术语规则中。每行一个术语，粘贴后会自动保存。

## 修复预览

点击单条结果的 `修复` 后会直接修改当前这一处。该操作只校验和更新当前文本图层，适合用户已经通过 `定位` 查看具体问题后的快速处理。

点击 `全部修复` 后，会先显示：

- 受影响的文本图层数量
- 问题总数
- 新增空格数量
- 多余空格数量
- 术语格式问题数量

统计区只用于确认即将修复的问题数量，不提供二次筛选，也不重复展示逐条问题。顶部突出全部问题总数和受影响图层数，下方分别展示缺少空格、多余空格和术语格式的数量及细分来源。其中 `多余空格` 包含行首尾、中文间、中文标点旁、角标左右和连续多余空格，以及用户主动开启的数字间空格；启用 `清理多余空格` 时，该卡片会再次提示规则可能影响刻意保留的排版空格。

弹窗打开后，滚轮只会滚动弹窗中的预览列表，不会带动下层检查结果。确认前会按当前扫描范围重新读取文案。

## UI 视觉规范

插件界面采用 Apple 系统界面的视觉原则，并同时适配浅色和深色模式：

- 使用系统字体栈，优先 `-apple-system`、`SF Pro` 和 `PingFang SC`。
- 软件名标题使用设计稿中的 `DIN Next Slab Pro Medium` 导出为 outline SVG，避免运行环境缺少字体时回退。
- 页面背景、内容面板和次级区域使用三级中性色建立层级，避免大面积高对比边框。
- 主强调色统一使用 Apple 官网常见的 CTA 蓝 `#0071E3`；选中背景使用低透明度版本，控制蓝色占比。
- 蓝色只用于主操作、选中状态、修复结果差异和键盘焦点。
- 成功、警告和危险状态分别使用系统绿、黄、红，不作为常驻装饰色。
- 普通控件圆角为 `9px`，结果卡片为 `12px`，弹窗为 `16px`。
- 卡片主要通过背景层级和轻阴影分组；边框保持低对比度。
- 动画控制在 `80–140ms`，只反馈按压、悬停和状态变化。
- 保持 `420px` 插件宽度和现有信息密度，不使用大标题、装饰插画或冗余图标。
